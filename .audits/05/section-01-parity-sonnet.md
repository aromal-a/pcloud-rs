### Row 124 — `psync_crypto_share_folder`
**Status: CONFIRMED PARTIAL (MEDIUM)**

- C source: `pclsync/psynclib.h:1009`
- Rust: `crates/pcloud-crypto/src/share_temppass.rs`, `crates/pcloud-backends/src/shares_backend.rs`
- Implemented: AES-256-GCM wrap + HMAC-SHA256 signature (Argon2 KEK). Share invitations generated by the Rust client are **non-functional for C-client recipients** because the C client's `prsa_sign_sha256_hash(crypto_privkey, …)` step (RSA-4096 signing) is absent.
- Comment at `share_temppass.rs:212`: _"substitute for the C client's RSA signature … The RSA swap is tracked under bd-1du.5."_
- **Remediation**: Store RSA-4096 keypair on the active Rust path; implement `prsa_sign_sha256_hash` equivalent; update temppass derivation to emit RSA-signed invitation blob. Bead `bd-1du.5` open.

## KAT Proof Soundness

### Fixture file sizes (committed)
- `kat-plaintext-v1.bin`: 4096 B (exactly one sector)
- `kat-ciphertext-v1.bin`: 4128 B (4096 B ct + 32 B detached auth tag)
- `kat-file-sym-key-wrapped.bin`: **512 B** (exact RSA-4096 block — resolved from the 504-byte issue documented in the test)
- `kat-folder-sym-key-wrapped.bin`: 512 B

The test source at `crates/pcloud-crypto/tests/pclsync_compat_kat_live.rs:132` is gated `#[ignore]` and additionally double-gates on `PCLOUD_KAT_PASSWORD` env var. This is correct — CI does not expose the real account password.

### HIGH — KAT fixture README metadata is incomplete
**File**: `crates/pcloud-crypto/tests/fixtures/pclsync_v2/README.md:18-19`
```
- iterations hint: ``
- salt hint (may be empty — salt lives inside priv_key_ver1 blob): ``
```
Both fields are empty. The test hardcodes `PCLSYNC_PBKDF2_ITERATIONS = 20_000` (`crates/pcloud-crypto/src/pclsync_kdf.rs:50`). If the server returns a variable iteration count in `crypto_getuserkeys`, a changed account would break without indication.
- **Remediation**: The extractor script (`scripts/extract-pclsync-kat.py`) should capture the `iterations` field from `crypto_getuserkeys` and write it into the README. The KDF module should accept an iteration count parameter so future accounts or changed settings are handled.

### MEDIUM — KAT test only covers sector 0
The live KAT validates a single 4096-byte sector (sector index 0). It does not prove cross-sector nonce/HMAC independence (collision resistance between `sector_id=0` and `sector_id=N`). The `pclsync_sector` unit tests should include a two-sector round-trip asserting that sector 0 and sector 1 ciphertexts differ and each decrypts correctly.
- **File**: `crates/pcloud-crypto/tests/pclsync_compat_kat_live.rs` (single-sector scope)
- **Remediation**: Add a multi-sector round-trip unit test in `crates/pcloud-crypto/tests/round_trip.rs` or a new `multi_sector.rs` file.

### LOW — `kat-file-hash.txt` not consumed by the KAT test
The extractor commits `kat-file-hash.txt` (the pCloud file hash, a u64) but the test does not use it. The comments in the test explain this correctly (file hash participates in the hash-tree auth in `pfscrypto.c:237-248`, not in the sector HMAC). No action required, but the fixture file is orphaned and may confuse future auditors.
- **Remediation**: Add a comment in `README.md` clarifying that `kat-file-hash.txt` is retained for future hash-tree auth verification, not for sector-level KAT.
