# Transfers, sync, backup, and mounted drives

These features turn namespace operations into durable byte movement and
continuous reconciliation. They share one rule: pCloud and the durable local
state decide truth; a warm cache or a delivered filesystem event never does.

```text
local bytes ── staging/journal ── upload session ── pCloud
     ▲               │                    │
     │               └── crash replay ────┘
     │
watcher + scanner → diff/planner/scheduler → conflict policy
     │
kernel mount adapter ── page/metadata cache ── RemoteFs
```

## Upload features

| Feature | What and why it exists | Good for, and why | Entrypoint / maturity |
|---|---|---|---|
| Generic streaming upload | Reads an exact declared number of bytes and commits them through a pCloud upload session. It exists so callers can upload any `Read` source without buffering the whole object. | SDK/gateway generated data and normal files. Short and overlong sources fail explicitly, preventing truncated or concatenated publication. | `RemoteFs::write_stream`, transfer backend; implemented |
| Explicit upload sessions | Exposes begin, chunk, status, commit, and abort with visible upload ID/acknowledged offset. It exists for large or interactive clients that must control chunking. | Multi-GiB uploads, progress UI, pause/resume, and unreliable links. Server acknowledgment rather than bytes merely written drives progress. | `begin_streaming_write` family, `UploadSession`; implemented; public SDK surface is intentionally narrower than embedded SDK |
| Durable file upload | Binds local path, size/hash identity, remote destination, session, and acknowledged offset to SQLite plus an append journal. It exists so a process crash or reboot does not require blind restart. | Long uploads, NAS, desktops, and release E2E. Resume occurs only when durable identity still matches the source and remote intent. | `upload_file_resumable[_to_parent]`, upload-resume repository/journal; implemented |
| Conflict modes | Supports overwrite, conditional overwrite by hash, or create-if-new. It exists because retrying a non-idempotent upload without an explicit collision rule can destroy data or duplicate it. | Sync, backup, and automation with different safety requirements. The conflict choice is part of persisted intent rather than inferred after failure. | `RemoteFs::UploadConflict`, protocol conflict parameter; implemented |
| Upload integrity | Computes and verifies SHA-1 where the pCloud upload path expects it before publication. It exists because byte count alone cannot detect corruption. | Durable local-file uploads and migration. Hash identity also prevents resuming against a changed source. | transfer backend/RemoteFs; implemented |
| Upload-session registry | Lists, pauses, resumes, cancels, and records active sessions. It exists to give users and shutdown logic control over long work. | CLI pending/progress, graceful drain, support, and restarts. A central registry avoids orphaned per-client state. | `pcloud-backends::upload_sessions`; implemented |
| Upload write-from-file compatibility | Reaches the pCloud file-backed upload verb used by legacy parity. It exists for API completeness and specialized server-side behavior. | Compatibility/migration tests. Current live E2E proves verb reachability with synthetic IDs rather than a complete successful lifecycle, so it is not the main durable path. | protocol upload methods and embedded SDK; implemented API path, limited live proof |
| Bandwidth pacing | Applies token-bucket limits to transfer I/O. It exists so sync cannot saturate a user's or site's link. | Interactive desktops, metered links, and shared WANs. Pacing is centralized and measurable rather than sleeping in each caller. | engine transfer bandwidth, resilience pacing; internal implemented |
| Time/metered scheduling | Changes bandwidth policy by schedule and network classification. It exists to make “fast at night, conservative on mobile data” declarative. | Laptops, branches, and NAS uplinks. A schedule applier drives the same pacer, and metered detection is a policy input rather than a separate transfer implementation. | config bandwidth schedule, daemon applier/metered detector; evolving |
| Differential upload planning | Uses rsync-style rolling/strong block signatures to identify changed blocks. It exists to avoid sending an entire large object after a small edit. | VM images, archives, and large frequently edited files. Weak rolling matches are confirmed by a strong hash, balancing speed and collision safety. | `pcloud-rsync`, engine differential strategy; experimental/partial until server path qualification |

## Download features

| Feature | What and why it exists | Good for, and why | Entrypoint / maturity |
|---|---|---|---|
| Signed-link download | Resolves `getfilelink` metadata and streams HTTPS bytes from the returned host/path. It exists because pCloud separates authorization/control from bulk data transfer. | CLI, SDK, sync, mount, and restore. Typed link parsing and shared rustls configuration contain redirect/host/integrity behavior. | transfer backend, `pcloud-proto::http_download`; implemented |
| Atomic download publication | Writes to a partial file, flushes/syncs it, verifies SHA-256, then publishes the destination. It exists so a final-looking path never represents an incomplete transfer. | Scripts, sync, restore, and power-loss-prone appliances. Partial and final states are unambiguous. | `RemoteFs::download_to_path`; implemented |
| Resumable download | Persists sidecar state bound to remote path, file ID, expected size, and local byte count. It exists to continue interrupted downloads safely. | Large files and intermittent connections. Resume is refused if identity no longer matches, preventing mixed-version files. | `download_by_id_*_to_path`; implemented |
| Range download | Fetches bounded byte ranges and reports total size/EOF. It exists for random-access consumers that do not need a whole file. | Mount page reads, media seeking, and gateway ranges. The 16 MiB per-call allocation cap limits memory abuse. | `RemoteFs::read_range`; implemented |
| Parallel-range planner | Splits a large object into independent HTTP ranges. It exists to exploit available bandwidth where the service supports ranges. | Large downloads on high-bandwidth/high-latency links. Typed ranges and final integrity checks keep concurrency from changing file semantics. | `pcloud-proto::parallel_download`; experimental T2.2, requires throughput/live qualification |
| Async transfer envelopes | Models asynchronous upload/download status where the protocol offers it. It exists so blocking and async control paths share typed wire meaning. | Embedded or future async integrations. It is transport support, not a requirement for the public blocking SDK. | `pcloud-proto::async_transfer`; internal |

## Synchronization engine

| Feature | What and why it exists | Good for, and why | Entrypoint / maturity |
|---|---|---|---|
| Sync-root lifecycle | Adds/lists/removes roots after canonicalizing the local path and validating the remote folder. It exists to keep overlapping or invalid roots out of persistent state. | Initial setup and automation. Duplicate/nested roots become typed conflicts rather than ambiguous traversal. | sync backend, store sync graph, CLI `sync`; implemented |
| Direction/type | Models bilateral/full, download-only/mirror, and upload-only behavior. It exists because propagation rules differ by use case. | Desktop synchronization, local mirrors, and upload-oriented workflows. Direction is persisted with the root and consumed by planning. | `SyncType`, `sync change-type`; implemented; upload-only is not deletion-safe archival backup |
| Local scanner | Walks the filesystem to establish or repair local state. It exists because watchers can overflow, be disabled, or miss downtime. | Initial convergence and repair. A complete scan provides a durable baseline independent of transient events. | `pcloud-engine::local_scan`; implemented |
| Filesystem watcher | Debounces native file events and feeds local changes to the engine. It exists for low-latency reaction between full scans. | Interactive edits. Max-age handling prevents continuous churn from postponing an event forever. | `pcloud-fs::fs_watcher`; implemented with native backend qualification |
| Remote diff polling | Reads server changes since a persisted cursor and dispatches typed diff events. It exists to discover remote mutations efficiently. | Continuous sync and shared folders. Per-root cursors in SQLite make restart continuation explicit. | proto diff API, engine diff poller/events, store diff state; implemented |
| Candidate planner | Converts observed local/remote differences into operations. It exists to separate “what changed” from “what should be done.” | Deterministic tests, policy insertion, and conflict analysis. Pure typed candidates are easier to reason about than side effects during scanning. | `pcloud-engine::planner`; internal implemented |
| Priority scheduler | Orders planned work by priority. It exists so interactive/small or recovery-critical work need not wait behind bulk transfers. | Responsive clients and bounded background work. One queue exposes ordering instead of relying on thread timing. | `pcloud-engine::scheduler`; internal implemented |
| Reconcile worker | Continuously executes plan work and updates state. It exists to own convergence rather than making CLI invocations drive sync. | Long-running daemon sync. Recovery classification and durable state survive transient failures. | `reconcile_worker`, daemon sync-loop runtime; implemented |
| Selective sync | Includes/excludes paths by configured patterns. It exists to avoid downloading or uploading irrelevant/sensitive subtrees. | Limited disks, source trees, and compartmentalization. Policy is evaluated before planning, and pattern lists are explicit per root. | `pcloud-engine::selective`, CLI exclude commands; implemented |
| Ignore patterns | Applies filename glob rules compatible with sync settings. It exists for temporary/build/system files that should never enter the plan. | Developer trees and OS noise. One matcher prevents CLI, scanner, and backend disagreement. | `pcloud-backends::ignore_patterns`; internal implemented |
| Conflict resolver | Classifies concurrent local/remote changes and selects preservation behavior. It exists because last-writer-wins can silently discard user data. | Bilateral sync. Typed conflict outcomes and conflict-copy naming make preservation visible. | `pcloud-engine::conflict_resolver`, model conflict types; internal |
| Recovery classifier | Maps failures to retry, restart, conflict, or terminal handling. It exists so retries are based on idempotency and cause rather than “try everything again.” | Network outages, expired links, changed files, and restart. Shared classification avoids per-transfer inconsistency. | `pcloud-engine::recovery`; internal implemented |
| Stall detector | Detects work that remains active without progress. It exists because a hung transfer can otherwise look healthy indefinitely. | Soak tests and operator alerts. Progress timestamps make the decision measurable. | `pcloud-engine::stall_detector`; internal |
| Divergence sweeper | Periodically compares expected and observed sync state. It exists to repair drift that neither watcher nor diff stream resolved. | Long-lived roots and post-crash repair. It is a safety net, not a competing sync engine. | `pcloud-engine::divergence_sweeper`; internal |
| Pause/resume | Stops and restarts synchronization without logging out or destroying root configuration. It exists for maintenance and user control. | Metered periods, troubleshooting, and upgrades. Central runtime state affects all workers consistently. | IPC `PauseSync`/`ResumeSync`; implemented |
| Power awareness | Supplies battery/AC state to sync and sweeper policy. It exists to avoid expensive scans on constrained laptops. | Mobile systems. Injectable power state is testable; platform readers are narrow. | engine/daemon power modules; implemented with platform qualification |

## Cache and local acceleration

| Feature | Why it exists and what it does | Good for, and why | Entrypoint / maturity |
|---|---|---|---|
| Metadata cache | Keeps recent lookup/getattr/readdir results with LRU and TTL bounds. It exists to avoid round-trips on repeated kernel/UI lookups. | Mounted drives and browsing. Expiry and RemoteFs fallback prevent cache state becoming authority. | fs metadata cache / pcloud-cache; internal implemented |
| Page cache | Retains bounded file pages keyed by typed identifiers. It exists for repeated/random reads. | Mount workloads and media access. Typed keys, LRU eviction, and configured memory budgets limit stale/memory behavior. | fs/cache page-cache units; internal implemented |
| Checksum cache | Reuses local checksums when file identity is unchanged. It exists because hashing large files repeatedly is expensive. | Sync planning and integrity scans. Entry bounds and identity checks contain staleness. | `pcloud-cache::checksum_cache`; internal |
| Staging buffers | Hold pending writes before durable flush. It exists to bridge small/random filesystem writes to sequential cloud uploads. | Mounted-drive editing. Memory and disk staging are separate and bounded. | cache/fs staging; internal |
| Cache encryption at rest | Seals disk-shaped cache blobs. It exists because local cached content may be as sensitive as remote content. | Shared disks and enterprise endpoints. A dedicated cipher/blob envelope avoids pretending ordinary LRU memory is encrypted. | `pcloud-cache::{cipher,sealed_blob}`; optional internal T2.3 |
| Eviction policy | Makes retention/eviction intent explicit. It exists so cache pressure behavior is configuration rather than incidental container order. | Predictable memory/disk limits. A policy tag can evolve without changing cache callers. | `pcloud-cache::eviction`; internal |

## Mounted-drive filesystem

| Feature | Why it exists and what it does | Good for, and why | Entrypoint / maturity |
|---|---|---|---|
| Portable adapter contract | Defines backend operations and inode/path semantics independent of a kernel ABI. It exists so Linux, BSD, macOS, and Windows do not implement different cloud behavior. | Cross-platform drive mounting. Native shims translate into one adapter and RemoteFs path. | `pcloud-fs::{backend,fuse_adapter}`; evolving core |
| Stable inode table | Maps remote paths/IDs to inode numbers bidirectionally. It exists because kernels expect stable integer identity while pCloud exposes file/folder IDs and paths. | `lookup`, `getattr`, `readdir`, rename, and cache invalidation. One table prevents recycled/mismatched identity. | `pcloud-fs::inode`; internal implemented |
| Path normalization | Canonicalizes filesystem inputs before remote resolution. It exists to block traversal/alias ambiguity and platform separator drift. | Every mount operation. Central validation avoids per-handler security differences. | `pcloud-fs::path_norm`; internal implemented |
| Read path and prefetch | Satisfies offset/length reads through bounded page caching and optional prefetch. It exists to make cloud latency tolerable to ordinary file applications. | Sequential readers and random access. Exact offset handling, EOF metadata, and cache bounds preserve POSIX-like semantics. | `pcloud-fs::read_path`; implemented core |
| Write staging | Writes incoming bytes to disk-backed staging before remote publication. It exists because kernel writes are partial/out-of-order while pCloud upload is session/stream oriented. | Editors and applications using small writes. Staging forms a coherent local image before flush. | `pcloud-fs::staging`, `write_path`; implemented core |
| Write-ahead journal | Records pending write/flush intent in crash-recoverable order. It exists so acknowledged local writes are not forgotten after process death. | Power loss, daemon crash, and replay. Checksummed/ordered records distinguish pending from completed work. | `write_journal`, `journal`; implemented core |
| Writeback service | Coordinates staged data, journal transitions, remote flush, and completion. It exists to turn filesystem close/fsync into a durable remote operation. | Mounted-drive writes. State transitions and replay tests make failure boundaries explicit. | `pcloud-fs::writeback`; implemented core, kernel E2E varies by platform |
| Mount policy | Controls read-only, `allow_other`, options, and default mountpoint. It exists because mounting changes local security boundaries. | Desktop and server deployments. Typed options and platform validation reject unsupported/unsafe combinations. | `pcloud-fs::mount`, config mount; implemented |
| Lifecycle/orphan handling | Discovers mounts, unmounts on shutdown, and cleans stale/orphan registrations. It exists because crashed daemons can leave kernel resources behind. | Upgrades, crashes, and service restarts. Platform mount discovery plus explicit cleanup supports a real “end” state. | mount service/orphan + daemon mount runtime; implemented core |
| Linux mount | Uses `fuser`/libfuse and `/dev/fuse`. It exists for native Linux drive semantics. | Linux desktops/servers/NAS kernels with FUSE. The thin platform adapter reuses the portable core. | `platform/linux`, `fuser_shim`; source implemented, native kernel qualification required |
| BSD mounts | Uses `fuser` with FreeBSD/NetBSD/OpenBSD/DragonFly-specific cfgs. It exists to make BSD a first-class source target rather than “probably Unix.” | BSD workstations/servers. Narrow cfg modules isolate ABI and mount-info differences. | `platform/bsd` and platform fuser shim; source implemented, each BSD needs native qualification |
| macOS mount | Uses direct fuse-t/macFUSE-shaped FFI and backend selection. It exists because macOS is not served by the Linux libfuse ABI. | macOS Finder/application access. Dedicated FFI and live mount suite keep native behavior explicit. | `platform/macos[_ffi]`; source implemented, entitlement/extension/native E2E required |
| Windows mount | Uses thin hand-written WinFSP FFI and Win32 volume discovery. It exists because Windows drive letters and filesystem callbacks differ completely from FUSE. | Explorer and Windows applications. Owner process/SID, volume discovery, and a narrow WinFSP boundary preserve portable semantics. | `platform/windows`, `winfsp_ffi`; source implemented, WinFSP/MSVC native E2E required |
| Solaris-family no-mount path | Keeps portable CLI/API/runtime available while returning a clear unsupported mount adapter. It exists to avoid unsafe fake portability. | illumos/OmniOS/Solaris users who only need API/copy/share/sync-like non-kernel features. Compile-time platform ownership makes the limitation honest. | `pcloud-fs::platform`; explicit unsupported mount status |

## Backup, snapshots, and integrity

| Feature | Why it exists and what it does | Good for, and why | Entrypoint / maturity |
|---|---|---|---|
| Backup/device lifecycle | Creates/stops/deletes backup roots and devices through pCloud's backup APIs. It exists because server backup objects have a lifecycle distinct from sync roots. | pCloud-native backup integration and device cleanup. Typed device/folder IDs avoid conflating backup with ordinary sync. | backup protocol/backend/CLI/embedded SDK; implemented |
| Snapshot builder | Produces a tar archive, manifest, and consistent SQLite copy, with optional GPG encryption. It exists for deletion-safe archival and disaster recovery. | Operators needing point-in-time artifacts rather than upload-only mirroring. Manifest/hash and database VACUUM/copy provide a verifiable bundle. | `pcloud-backends::snapshot`, daemon snapshot pipeline; implemented internal/ops path |
| Snapshot pruning | Applies retention to old snapshots. It exists so DR storage remains bounded. | Scheduled backup operations. Explicit policy separates deletion from snapshot creation. | snapshot prune paths/live tests; implemented with operator validation |
| Integrity sweeper | Walks content/metadata and reports checksum divergence, with scheduling and battery policy. It exists to detect latent corruption outside active transfers. | Long-lived data, caches, and release soak. Bounded background work and pause-on-battery avoid harming foreground use. | fs integrity sweeper + daemon service/config; implemented, live scale qualification required |
| CLI verify | Walks a synchronized tree and compares SHA-256/integrity metadata. It exists as an on-demand operator proof. | Migration and support. Read-only reporting makes it safe to run before remediation. | `pcloud-cli::verify`; implemented |
| Auto-heal plugin | Converts repeated checksum findings into quarantine/pause requests. It exists to separate automated remediation policy from the scanner. | Managed endpoints willing to opt into repair automation. Capability-bounded messages stop the plugin from directly mutating arbitrary state. | `pcloud-plugin-autoheal`; optional experimental plugin |
| Backup schedule plugin | Emits backup cycles from cron or a small natural-language DSL. It exists to keep scheduling extensible and user-level. | Regular personal backups. Deterministic tick evaluation is testable without sleeping. | `pcloud-plugin-backup-schedule`; optional experimental plugin |
