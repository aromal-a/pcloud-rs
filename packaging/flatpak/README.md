# pcloud-rs Flatpak packaging

This directory contains the Flatpak manifest and desktop metadata for
`com.pcloud.pcloud-rs`, the Rust rewrite of the pCloud console client.

## Files

- `com.pcloud.pcloud-rs.yaml` — flatpak-builder manifest
- `com.pcloud.pcloud-rs.desktop` — freedesktop `.desktop` entry
- `com.pcloud.pcloud-rs.metainfo.xml` — AppStream metadata (required for Flathub)

## Prerequisites

Install the Flatpak SDK and the Rust extension:

```bash
flatpak install --user flathub \
    org.freedesktop.Platform//24.08 \
    org.freedesktop.Sdk//24.08 \
    org.freedesktop.Sdk.Extension.rust-stable//24.08
```

You also need `flatpak-builder`:

```bash
sudo pacman -S flatpak-builder    # Arch
sudo apt install flatpak-builder  # Debian/Ubuntu
```

## Local build and install

From the repository root:

```bash
flatpak-builder --user --install --force-clean \
    build-dir packaging/flatpak/com.pcloud.pcloud-rs.yaml
```

Run it:

```bash
flatpak run com.pcloud.pcloud-rs --help
```

## Testing the sandboxed runtime

- Confirm network access: `flatpak run com.pcloud.pcloud-rs login ...`
- Confirm FUSE mount works: try the mounted-drive command inside the sandbox.
- Confirm secret-service access for the opt-in auth-token vault.
- Confirm the `.desktop` and metainfo files validate:

```bash
desktop-file-validate com.pcloud.pcloud-rs.desktop
appstreamcli validate com.pcloud.pcloud-rs.metainfo.xml
```

## Submitting to Flathub

1. Fork `https://github.com/flathub/flathub`.
2. Create a submission branch:

   ```bash
   git checkout -b new-pr
   ```

3. In the fork, open a PR that adds a new folder `com.pcloud.pcloud-rs/`
   containing this manifest, the `.desktop` file, and the metainfo XML.
4. Before submitting, replace the `type: dir` source in the manifest with a
   tagged `type: git` source pointing at an upstream release tag, and add a
   vendored `cargo-sources.json` generated by
   [`flatpak-cargo-generator.py`](https://github.com/flatpak/flatpak-builder-tools/tree/master/cargo)
   so the build does not require network access.
5. Wait for the Flathub reviewers to test, request changes, and merge.
6. Once merged, the app will appear on https://flathub.org.

## Notes

- The manifest currently grants `--share=network` at build time so cargo can
  fetch crates. For Flathub, switch to vendored sources as described above.
- `--filesystem=home` is intentional: sync roots must live somewhere the user
  controls. Narrow this to `--filesystem=home/pCloud` if that matches your
  deployment policy.
- `--device=fuse` is required by the mounted-drive runtime (see `pcloud-fs`).
