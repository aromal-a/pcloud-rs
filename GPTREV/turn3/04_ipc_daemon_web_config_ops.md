# pcloud-rs Turn 3 Subagent 04 Audit

Scope: IPC, daemon lifecycle, web management, config/session/auth integration, platform services.
Result: 12 findings: 4 High, 7 Medium, 1 Low. No files were modified.

| ID | Severity | Finding |
|---|---:|---|
| H-01 | High | `set-api-server` persists rejected API servers and still reports success. Evidence: `crates/pcloud-daemon/src/runtime.rs:2889`, `crates/pcloud-daemon/src/runtime.rs:3475`, `crates/pcloud-config/src/api.rs:292`, `crates/pcloud-proto/src/transport.rs:418`. Impact: durable config/store inconsistency, daemon outage, misleading audit success, possible malformed host persistence. Remediation: make validation fatal, reject schemes/path/userinfo, only mutate/persist after validation, and cross-check against discovered API servers. |
| H-02 | High | `pcloud-web` exposes daemon-backed data without web auth. Evidence: unauthenticated `GET /sync` at `crates/pcloud-web/src/routes.rs:165`, `GET /publinks` at `crates/pcloud-web/src/routes.rs:252`, `GET /activity` at `crates/pcloud-web/src/routes.rs:401`, `GET /settings` at `crates/pcloud-web/src/routes.rs:436`; only `/api/status` is token-gated at `crates/pcloud-web/src/routes.rs:140`. Impact: any local loopback client can read sync roots, public links, notifications, and daemon socket path. Remediation: require `X-PCloud-Web-Token` or an authenticated session for every daemon-backed route except health probes; add Host/Origin checks. |
| H-03 | High | Packaged systemd service uses `Type=notify`, but the normal `pcloudd serve` path does not send `READY=1`. Evidence: `packaging/systemd/pcloudd.service:30`, `packaging/systemd/pcloudd.service:38`, daemon bind/serve path at `crates/pcloud-daemon/src/main.rs:122` and `crates/pcloud-daemon/src/main.rs:227`; `READY=1` only appears in alternate paths at `crates/pcloud-daemon/src/serve.rs:462` and `crates/pcloud-daemon/src/serve.rs:591`. Impact: service can remain activating and fail despite binding the socket; watchdog semantics are unreliable. Remediation: emit `sd_notify("READY=1")` after successful bind/startup in `pcloudd serve`, or change the unit to `Type=simple`. |
| H-04 | High | Windows service wrapper reports clean SCM stop even after worker error or panic. Evidence: errors swallowed at `crates/pcloud-daemon-win/src/main.rs:159`, join failures discarded at `crates/pcloud-daemon-win/src/main.rs:246`, final status always `Win32(0)` at `crates/pcloud-daemon-win/src/main.rs:257`. Impact: SCM recovery policies and operators cannot distinguish crashes from intentional clean stops. Remediation: preserve worker result, report nonzero `ServiceExitCode`, log to Event Log, and add service-failure tests. |
| M-01 | Medium | Web CSRF design makes no-JS HTML mutation forms unusable. Evidence: header-only CSRF checks at `crates/pcloud-web/src/routes.rs:206` and `crates/pcloud-web/src/routes.rs:295`, `HttpOnly` CSRF cookie at `crates/pcloud-web/src/routes.rs:761`, CSP blocks scripts at `crates/pcloud-web/src/routes.rs:61`, rendered forms lack hidden tokens at `crates/pcloud-web/src/routes.rs:815` and `crates/pcloud-web/src/routes.rs:843`. Impact: browser users get 403 on legitimate form submissions, encouraging unsafe bypasses. Remediation: use server-side CSRF tokens in hidden form fields, or intentionally use JS-readable double-submit tokens with CSP adjusted and tested. |
| M-02 | Medium | Web token is stored as a plain `String` inside a `Debug`-derived config. Evidence: `crates/pcloud-web/src/lib.rs:194`. Impact: debug logs or error reports can leak the bearer token that authorizes web mutations. Remediation: store the token as `SecretString` or a redacted wrapper and implement redacted `Debug`. |
| M-03 | Medium | Web token file writing lacks the hardening used by the auth vault. Evidence: `crates/pcloud-web/src/lib.rs:316` creates/truncates `web-token`, ignores chmod failure, does not use `create_new`, `O_NOFOLLOW`, temp+rename, final metadata verification, or parent ownership validation. Impact: pre-existing permissive files, symlinks, or weak runtime-dir metadata can leak the web token. Remediation: validate parent owner/mode, write via 0600 temp file plus atomic rename, reject symlinks/non-regular files, `sync_all`, and verify final mode. |
| M-04 | Medium | IPC runtime-directory hygiene is not fail-closed. Evidence: `crates/pcloud-ipc/src/transport.rs:711` chmods only if the existing parent is owned by the daemon UID and otherwise proceeds; bootstrap chmods paths without symlink/owner validation at `crates/pcloud-daemon/src/bootstrap.rs:441`. Impact: attacker-prepared or misconfigured runtime directories can enable socket squatting, DoS, or token-placement weaknesses. Remediation: use `symlink_metadata`, reject symlinks/non-directories, require owner equals effective UID and mode no broader than 0700, and verify after chmod. |
| M-05 | Medium | IPC clients allocate response payloads before enforcing maximum size. Evidence: Unix client `read_to_end` at `crates/pcloud-ipc/src/transport.rs:790`; Windows client allocates `vec![0u8; payload_len]` before cap validation at `crates/pcloud-ipc/src/transport.rs:804`; protocol cap exists later at `crates/pcloud-ipc/src/protocol.rs:321`. Impact: malicious or stale endpoints can OOM CLI/web clients. Remediation: read fixed header first, validate kind/version and `payload_len <= MAX_IPC_PAYLOAD_LEN`, then allocate and read exact payload. |
| M-06 | Medium | IPC protocol decoders do not reject unexpected message kinds. Evidence: request decoder records but accepts non-request kinds at `crates/pcloud-ipc/src/protocol.rs:293`; response decoder does the same at `crates/pcloud-ipc/src/protocol.rs:343`. Impact: malformed frames pass semantic validation, weakening fuzz safety and future compatibility boundaries. Remediation: add `UnexpectedMessageKind` errors and tests for request/response/event mismatches. |
| M-07 | Medium | Shipped systemd socket unit is not actually wired to the daemon and uses a different path. Evidence: socket unit listens on `%t/pcloud-rs/daemon.sock` at `packaging/systemd/pcloudd.socket:5`; service says socket activation is not required at `packaging/systemd/pcloudd.service:14`; daemon binds its own path at `crates/pcloud-daemon/src/main.rs:122`; default socket path is `pcloud.sock` under `$XDG_RUNTIME_DIR/pcloud/pcloud-rs` at `crates/pcloud-config/src/paths.rs:82` and `crates/pcloud-config/src/paths.rs:183`. Impact: enabling the socket unit creates a dead listener and its connection caps do not protect the real daemon. Remediation: remove/disable the socket unit or implement `LISTEN_FDS` socket activation and align paths. |
| M-08 | Medium | Orphan mount crash-recovery rejection logs an error but continues startup. Evidence: `crates/pcloud-daemon/src/bootstrap.rs:802`. Impact: daemon can appear healthy while mount service is refused or unsafe after stale orphan detection. Remediation: fail bootstrap, mark mount subsystem explicitly disabled in health/status, or ensure all later mount operations fail with a structured error. |
| L-01 | Low | macOS launchd packaging overrides production API host to `api.pcloud.com` instead of the binapi default. Evidence: `packaging/macos/com.pcloud.pcloudd.plist:109`; default binapi host is `bineapi.pcloud.com:443` at `crates/pcloud-config/src/api.rs:196`. Impact: packaged daemon may bypass the tested default transport endpoint or fail binary protocol connection. Remediation: remove the override or set `PCLOUD_API_HOST` and `PCLOUD_API_SERVER_NAME` to the binapi endpoint. |

## Positive Controls Observed

Unix IPC peer credentials are enforced in the server path, including same-UID authorization. Windows named-pipe code builds owner-SID ACLs and checks connecting clients. Server-side IPC request framing has payload caps. The file auth vault uses stronger temp-file, mode, owner, and parent-directory validation than the web token writer.

## Limitations

This was a read-only source audit. I did not run builds, tests, service managers, browser sessions, systemd units, launchd jobs, or Windows SCM integration. I focused on primary implementation files and packaging paths in the requested scope; tests and generated outputs were not exhaustively reviewed.
